# AGENTS.md

HYA Tech corporate site: Next.js 16 (App Router, Turbopack), React 19, TypeScript (strict), Tailwind CSS v4. No testing framework. No CMS — content lives in local TS data files.

## Commands

- `npm run dev` — dev server (uses port 3000; picks 3001 if 3000 is taken). A dev server is often already running — check before starting.
- `npm run build` — production build; also runs the TypeScript check. This is the main verification step.
- `npm run start` — serve the production build (requires `npm run build` first).
- `npm run lint` — **NOT clean by default**: 1 pre-existing error (`react/no-unescaped-entities` in `src/components/home/about-preview.tsx`) plus 2 unused-import warnings (`process-steps.tsx`, `capabilities.ts`). Do not "fix" these or treat them as your regression; diff against `git status` instead.
- No test script, no typecheck-only script, no formatter/lint-fix config. Don't invent one.

## Architecture

- `src/app/*/page.tsx` — route pages (about, capabilities, careers, contact, privacy, projects, terms).
- `src/components/` — feature folders (`home/`, `about/`, `contact/`, `projects/`, `careers/`, `capabilities/`) plus shared pieces: `page-hero.tsx`, `header.tsx`, `footer.tsx`, `location-grid.tsx`, `flags.tsx`, `timeline.tsx`, `ui.tsx`.
- `src/data/` — all content (site info, locations, projects, careers). Edit copy/data here, never hardcoded in components.
- `src/lib/metadata.ts` — shared metadata. `src/app/api/contact|careers` — form POST routes.
- `@/*` aliases to `src/*`.

## Styling (easy to get wrong)

- Tailwind v4 is CSS-first: `@import "tailwindcss"` + `@theme inline` in `src/app/globals.css`. **There is no `tailwind.config.js`.**
- Global styles contain a large custom design-system layer (`@layer components`: `.soft-card`, `.page-hero-*`, `.location-card`, `.office-location-grid`, `.site-container`, plus `.dark` overrides). Many UI decisions live in that CSS, not in utility classes. When changing layout, check both the JSX utilities and globals.css.
- Dark mode is driven by `html.dark` + `.dark .x` overrides in globals.css. Test both modes.

## PageHero gotchas

- `page-hero.tsx` renders every page hero via a `variant` prop (`"page" | "home" | "about"`).
- The **About page passes no `variant`, so it renders the default `page` variant**. The entire `.page-hero-about` / `.page-hero-card-about` CSS block is currently dead code. Scope About-specific hero styles with `.page-hero-page .page-hero-highlights` (only About + Home pass `highlights`, and they differ by variant class, so this selector is About-only).
- Home hero vertical offset is tuned via `.page-hero-home-container` `padding-top` (this is the knob used for the 10px hero shift).

## Contact page office cards

- `src/components/contact/office-explorer.tsx` renders the map (`office-map.tsx`, Leaflet/react-leaflet) beside `office-location-grid` cards under `lg:grid-cols-[1fr_1.2fr]`.
- The card grid is 6 columns with staggered spans (5 cards, spans `2`, `2/span 2`, `4/span 2`). **Keep this structure** — changing columns/ordering is explicitly off-limits in this project.
- On desktop the cards are only ~199px wide, so true `aspect-ratio: 1/1` squares physically cannot hold the content (it clips). Squares (`aspect-ratio: 1/1` + `align-self: start`) are applied only in the ≤1023px breakpoints; desktop uses `grid-auto-rows: 1fr` for uniform equal-height tiles instead. Preserve this behavior.
- Badge + flag are intentionally pinned to the card's top-right (`shrink-0` column; left content has `min-w-0`). Don't reintroduce `flex-wrap` there — it made them wrap to the left on narrow cards.

## Repo hygiene

- `.gitignore` covers `.env*`, `node_modules`, `.next`, `.chrome-qa`, `qa-screenshots`. Do not commit those.
- `next-env.d.ts` is auto-regenerated by `next dev`/`next build` and **flips between importing `.next/dev/types/routes.d.ts` and `.next/types/routes.d.ts`** depending on what last ran. It appears as modified in `git status` sporadically — never edit or hand-commit it; ignore transient changes.
- `hya-tech-wordpress-theme/` (+ the `.zip`) is a separate WordPress theme, unrelated to this app. Don't touch it for app work.

## Workflow

- Single branch `main`, origin `github.com/vrkavin003-hub/hya-website.git`, commits pushed directly (no PR flow).
- Commit messages are short and human (e.g. "Update latest website changes", "Improve mobile responsiveness without affecting desktop layout").
- Windows shell (PowerShell); git may warn about LF/CRLF on files you touch — harmless.
- `docs/product-specification.md` records the client-verified content brief; treat it as the source of truth for published claims.
- Validation for UI changes: `npm run build` + visual/browser QA (screenshots historically saved to `qa-screenshots/`, a Chrome profile in `.chrome-qa/` was used for headless QA).
